# 덱 개정 지침 (2026-11-18)

발표 덱 전체를 다시 쓴다. 목표는 하나다. **장마다 말하려는 것 하나가 3초 안에 읽혀야 한다.**
청중은 한국공항공사 기록관리 담당자와 경영진이다. 개발자가 아니다.

먼저 읽을 것: `SLIDE_GUIDE.md`(장 등록 형식, 결정성, 검수 방법), `kit.js`(부품), `deck.css`, 그리고 본보기 장 `slides/s02a_roles.js`.
`SLIDE_GUIDE.md`와 이 문서가 다르면 이 문서를 따른다.

## 1. 한 장에 주장 하나

- 제목이 그 장의 주장이다. "~다"로 끝나는 문장으로 쓴다. 본문은 그 주장을 보여 주는 그림 하나와 큰 숫자·짧은 이름표로 만든다.
- 지금 한 장에 두세 가지가 들어 있으면 **장을 나눈다**. 장 수가 늘어도 된다. 한 장을 2~4장으로 나눠도 좋다.
- 제목과 본문이 같은 말을 되풀이하지 않는다. 부제(sub)는 꼭 필요할 때만 쓴다.

## 2. 화면에서 지울 것(발표자 노트로 옮긴다)

- 영문 에이전트 이름(`record-assigner` 등), 스크립트 파일 이름(`make_batches.py`), 폴더·파일 경로, JSON·코드 조각
- 모델 이름(opus, sonnet), 출처 줄, 각주, 예외 설명, "~는 ~다" 식의 보충 문장
- 같은 종류의 ID 나열. ID(`U0087`, `F0164`)는 예시로 한두 개만 보여 준다
- 한 화면에 작은 표·작은 범례가 여러 개 있으면 가장 중요한 하나만 남긴다

노트(`notes`)에는 지운 내용을 문장으로 적는다. 영문 에이전트 이름, 스크립트 이름, 출처 파일 경로는 노트에 꼭 남긴다.

## 3. 글자

- 크기 하한: 본문 28px, 보조 설명 24px, 표 셀 24px. **22px보다 작은 글자를 쓰지 않는다.**
- 제목을 뺀 본문 문장은 한 장에 3개 이하, 문장 하나는 30자 안팎. 이름표·숫자 단위는 문장으로 세지 않는다.
- 숫자가 주장이면 크게 쓴다(90px 이상).
- 표는 5행 이하, 4열 이하. 넘으면 그림으로 바꾸거나 장을 나눈다.

## 4. 말

한국어 화자가 평소에 쓰는 말로 쓴다. 사용자가 실제로 지적한 표현이 있다: "분류할 근거가 비어 있는 곳이 있다", "층위", "자기 분류기준표가 없다".

- **번역투 금지**: "~를 통해", "~에 있어서", "~에 대해", "~하는 것이 가능하다", "~을 가진다", "~로 인해", "~되어진다", 명사 여러 개를 '의'로 이은 말
- **비유 금지**: 은유·직유·의인화·관용적 비유 모두. 대상을 직접 가리킨다. ("빌려 쓴다", "걸러 낸다", "빈틈", "한눈에", "뼈대", "길잡이" 같은 말도 쓰지 않는다)
- **낯선 말을 쉬운 말로**

| 쓰지 않는다 | 쓴다 |
| --- | --- |
| 군집 | 묶음 (제목이 비슷한 문서 묶음) |
| 준용 | 다른 공항 기준표 적용 |
| 승계추정 | 없어진 부서(현재 부서로 추정) |
| 대조 모드, 초안 모드 | 기준표가 있는 부서 / 없는 부서 |
| 독립 판단, 블라인드 | 기존 분류를 보지 않고 다시 분류 |
| 불일치 | 판단이 다르다 |
| 파이프라인 | 진행 순서 |
| 재현율 | 넣어 둔 오류 중 찾아낸 비율 |
| 주입한 오류 | 시험용으로 넣어 둔 오류 |
| 근거 ID | 근거 번호 |
| 층위, 저촉, 상이, 수행, 도출, 산출물 | 쓰지 않는다. 풀어서 쓴다(규정에 어긋난다, 다르다, 한다, 낸다, 결과물) |

- 사람이 주어가 아닌 문장에 "확신", "생각" 같은 말을 쓰지 않는다. "정할 수 없으면", "판단이 다르면"처럼 쓴다.
- 판정 이름은 하네스 결과물에 실제로 쓰인 이름만 쓴다(확정, 확정(중재), 검토필요, 미배정, 보류, 정정 권고, 유지, 사람 확인, 통과, 수정필요, 기각, 타당 등). 새로 지어내지 않는다.
- 스크립트는 화면에서 "스크립트"라고만 부르고 하는 일을 짧게 적는다(예: "문서를 추린다").

## 5. 에이전트를 그림으로 보여 준다

에이전트를 글 상자(`K.agent`)로 그리지 않는다. **`K.actor`** 를 쓴다. 역할 그림 + 한글 이름표 + 하는 일 한 줄이 나온다.

```js
d.a1 = K.actor(root, { id: 'record-assigner', job: '철을 고른다', x: 230, y: 372, w: 260 });   // 한글 이름·역할은 K.AG 에서 가져온다
d.sc = K.actor(root, { kind: 'script', name: '스크립트', job: '문서를 추린다', x: 120, y: 400, w: 200 });
d.hu = K.actor(root, { kind: 'human', name: '사람', job: '검토하고 승인한다', x: 1600, y: 380, w: 170 });
// render 에서
d.a1.render(lt, 0.5);          // 등장
d.a1.act(lt, 지금_일하는_중);   // 참이면 그림이 위아래로 움직이고 이름표 테두리가 굵어진다
```

- 역할(kind)과 색: `make` 만들기(파랑), `check` 검증·반박(빨강), `judge` 판정·중재(주황), `write` 보고서(남색), `script` 스크립트(회색 점선), `human` 사람.
- 에이전트 18개의 한글 이름은 `kit.js` 의 `K.AG` 에 있다. 화면에는 이 한글 이름만 쓴다.
- 그림 폭은 180~280px. 그림 세로는 `w * K.AGR[kind]`. 이름표와 job 이 그 아래로 약 90~130px 더 내려온다. 겹치지 않게 계산한다.
- 반환값의 `cx`, `cy`, `top`, `bottom`, `w`, `h` 로 연결선 좌표를 잡는다.

## 6. 움직임으로 내용을 설명한다

장식용 움직임이 아니라 **그 장의 내용이 진행되는 모습**을 보여 준다. 실제 문서 제목 한 건이 에이전트를 차례로 거치고, 에이전트가 판단을 말하고, 결과 도장이 찍히는 과정을 되풀이해 보여 주는 식이다.

- `K.loop(lt, t0, [단계 길이…])` → `{ i, u, lap }`. 등장이 끝난 뒤 단계를 되풀이한다. `lap` 으로 바퀴마다 다른 사례(같다 / 다르다)를 보여 줄 수 있다.
- `K.doc(root, '문서 제목', {x, y})` 문서 카드. `K.travel(el, lt, t0, dur, [x0,y0], [x1,y1], { arc })` 로 옮긴다.
- `K.say(root, '저는 다릅니다', {x, y}, 'bad')` 에이전트의 판단 한마디(ok | warn | bad | blue | ink).
- 기존 부품도 쓴다: `K.draw`(선), `K.dots`(선 위 점), `K.count`(숫자 세기), `K.stamp`(도장), `K.bar`, `K.wipe`, `K.cycle`, `K.type`.
- 모든 장에 (1) 3초 안에 끝나는 등장, (2) 머무는 동안 내용을 설명하는 반복 움직임 하나를 둔다. 단계 하나는 0.9~1.6초로 잡아 읽을 수 있게 한다.
- render 는 lt 만으로 화면을 정한다(`SLIDE_GUIDE.md` 의 결정성 규칙). 요소를 보였다 숨길 때는 opacity·transform 을 매번 직접 정한다.
- 본보기: `slides/s02a_roles.js` 의 `h-flow` 장.

## 7. 지킬 것

- **숫자와 사례는 지금 장에 있는 값과 하네스 결과 파일(`output/`, `_workspace/`, `kac-shared/data/`)에 있는 값만 쓴다.** 새로 계산해 쓸 때는 파일에서 직접 확인하고 노트에 출처를 적는다. 확인하지 못한 숫자는 쓰지 않는다.
- 맡은 장 파일만 고친다. `kit.js`, `deck.css`, `deck.js`, `index.html`, 다른 장 파일은 고치지 않는다. 필요한 함수는 자기 파일 안에 지역 함수로 만든다.
- 다른 파일이 찾는 장 id 는 그대로 둔다: `h-parts`, `h-human`, `summary`. 챕터 영상 장(`ch-…`, `video:` 가 있는 장)과 표지·필름 장은 고치지 않는다. 장의 `harness`, `chapter` 값은 지금 쓰는 값을 따른다.
- 새 장 id 는 지금 파일의 접두어를 따른다(예: `c2-…`).
- 오른쪽 위에는 하네스 그림(`wicon`, 약 x 1620~1830, y 30~230)이 자동으로 들어간다. 그 자리에 다른 것을 놓지 않는다.
- 이모지를 쓰지 않는다. 장식용 영문 대문자 라벨을 쓰지 않는다.
- 폰트는 지금 상용 한글 전체가 들어 있다. `tools/build_fonts.py` 는 실행하지 않는다.

## 8. 검수(꼭 한다)

```bash
cd harness-deck/deck
node tools/shoot.mjs --ids '<접두어>*' --times 1.2,4,7,10 --out ../qa/rev_<파일이름>
```

- `--ids` 는 장 id 로 고른다(`c2-*` 처럼 끝에 `*`). 다른 작업자가 동시에 장을 더하므로 `--pages` 번호는 쓰지 않는다. `--out` 폴더는 위 이름을 지킨다.
- 찍은 PNG 를 Read 로 직접 열어 본다(한 번에 한 장씩, 1920×1080). 볼 것: 겹침, 잘림, 화면 밖으로 나간 글자, 22px 미만 글자, 빈 공간이 한쪽에 쏠림, 움직임 단계마다 요소 위치.
- `pageerror` 가 나오면 반드시 고친다. `404` 한 줄은 무시한다.
- 고치고 다시 찍기를 2회 이상 한다. 다른 작업자의 파일 때문에 생긴 오류는 고치지 말고 보고한다.
