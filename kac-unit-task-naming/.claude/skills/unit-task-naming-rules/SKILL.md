# 단위업무명 제안 판단 기준

## 용어와 자료

- **단위업무**: 분류기준표에서 소기능 아래에 두는 업무 단위. 기록물철 1~5개를 거느린다(기존 703개 가운데 269개는 철 1개, 중앙값 2개).
- **군집**: 한 부서의 문서 제목을 글자 구성이 비슷한 것끼리 스크립트가 묶은 것. `c001` 형식은 일반 군집, `g01` 형식은 낱말표로 표시한 부서공통 추정 묶음이다.
- **모드**: 부서 대응 유형이 `직접`이면 `대조`(기존 단위업무와 비교), 그 밖(준용·승계추정·대상외)이면 `초안`(단위업무 목록을 새로 작성)이다. 초안 모드의 `existing_units.json`은 다른 부서 기준표이므로 참고만 한다.
- 대조 모드라도 기존 단위업무가 몇 개뿐인 부서(예: ESG경영실 1개)는 제안 대부분이 신설이 된다. 이때도 기존 단위업무는 빠짐없이 유지·개명·통합·폐지 검토 가운데 하나로 처리한다.

군집 자료의 한계를 알고 쓴다.

- 군집은 글자 구성으로 묶었으므로 한 군집에 다른 업무가 섞이거나 한 업무가 여러 군집으로 나뉜다.
- 상위 군집만 제시된다. `clusters.json`의 `통계`에서 제시 군집 문서 수와 소규모 군집 문서 수를 확인하고, 제시되지 않은 문서가 많으면 "없다"는 결론을 조심한다.
- `추정문서수`와 `기존단위업무_유사`는 글자 유사도로 센 참고값이다.

## 군집 해석

군집마다 대표제목 전체를 읽고 다음을 정한다.

| 항목 | 기준 |
| --- | --- |
| 업무내용 | "무엇을 대상으로 어떤 처리를 하는 업무인가"를 한 문장으로 쓴다. 제목에 나온 대상·행위만 쓴다. |
| 성격 | `고유업무`: 이 부서가 주관하거나 반복 수행하는 업무. `부서공통`: 복무·출장·지출·서무처럼 모든 부서가 하는 사무. `타부서 소관 수신`: 다른 부서·기관이 주관하는 일을 통보받은 문서가 대부분. `혼합`: 서로 다른 업무가 섞임. `판단불가`: 제목만으로 알 수 없음. |
| 기존단위업무 | 대표제목이 기존 단위업무의 이름·기록물철 범위에 들어가면 `일치`, 일부만 들어가거나 범위가 어긋나면 `부분`, 대응하는 것이 없으면 `없음`. |
| 임시업무명 | 고유업무일 때 업무를 가리키는 짧은 이름. 확정 이름이 아니다. |

성격을 가를 때 다음을 본다.

- 생산 문서가 많고 여러 해에 걸쳐 반복되면 고유업무일 가능성이 높다. 접수 문서뿐이고 발신처가 본사 한 부서이면 타부서 소관 수신일 가능성이 높다. 다만 민원·신청서처럼 접수해서 처리하는 것이 본업인 업무(예: 출입증 발급 신청 접수)는 접수가 대부분이어도 고유업무다.
- `g`로 시작하는 묶음은 기본적으로 부서공통이다. 그 사무의 주관 부서이면 고유업무로 본다. 예를 들어 출장·여비 문서는 대부분의 부서에서 부서공통이지만 여비 지급을 주관하는 총무 부서에서는 고유업무다. 주관 여부는 `existing_units.json`에 해당 업무가 있는지와 생산 문서의 수신처가 여러 부서인지로 판단한다.
- 한시적 사안(예: 2021년에만 있는 코로나 재택근무 편성)은 연도별 문서수로 확인하고 비고에 적는다.

## 제안 유형과 조건

| 유형 | 모드 | 조건 |
| --- | --- | --- |
| 신설 | 대조 | 고유업무 군집이 있는데 대응하는 기존 단위업무가 없다(적합도 `없음`, 또는 `부분`이지만 기존 단위업무의 범위를 넓히는 것이 맞지 않음). |
| 개명 | 대조 | 기존 단위업무에 대응하는 문서가 있으나 이름이 문서의 실제 대상·행위를 가리키지 못한다. 이름이 좁아 주요 문서가 빠지거나, 현재 쓰지 않는 명칭이거나, 다른 단위업무와 구별되지 않는 경우다. |
| 통합·폐지 검토 | 대조 | 기존 단위업무에 해당하는 문서가 거의 없거나, 다른 단위업무와 문서가 구별되지 않는다. 통합할 대상이 있으면 `통합대상_unit_id`를 적는다. |
| 유지 | 대조 | 이름과 문서가 맞는다. 문서가 적어도 법정·연례 업무로 판단되면 유지로 두고 사유에 적는다. |
| 초안 | 초안 | 고유업무 묶음마다 하나. 준용 참고 기준표에 같은 업무가 있으면 그 이름을 쓰고 `준용_unit_id`를 적는다. 부서 실정과 다르면 새 이름을 짓는다. |

공통 원칙은 다음과 같다.

- **업무 단위로 묶는다.** 군집 하나가 곧 단위업무는 아니다. 같은 대상에 대한 계획·시행·결과·정산 문서는 한 단위업무로 묶고, 그 안의 구분은 기록물철 초안으로 나눈다. 반대로 대상이 다르고 담당이 나뉘는 업무는 군집이 하나여도 나눈다.
- **부서공통과 타부서 소관 수신은 고유 단위업무의 근거로 쓰지 않는다.** 해당 군집은 보류에 넣고 사유를 적는다. 부서공통 사무는 부서공통 기준(비공개 세부기준의 부서공통 항목)으로 관리되기 때문이다.
- **근거가 기준에 못 미치면 낮춘다.** 근거 문서 수가 `통계.신설근거_최소문서수`보다 적은 신설·초안은 확신도를 `낮음`으로 하거나 보류한다.
- **개명은 보수적으로 한다.** 기존 이름은 담당부서 의견을 거쳐 정해진 것이다. 표현을 다듬는 수준의 개명은 제안하지 않고, 범위나 명칭이 문서와 어긋나는 경우에만 제안한다.
- **통합·폐지 검토는 검토 요청이다.** 문서목록에 없다는 사실은 업무가 없다는 증거가 아니다. 사유에 확인한 범위(연도, 제시 군집 비율)와 가능한 다른 설명을 적는다.
- **모든 군집을 처리한다.** 제시된 군집은 어떤 제안의 근거가 되거나 보류에 사유와 함께 들어가야 한다.

## 이름 짓기

`references/naming-conventions.md`를 읽고 따른다. 요점은 다음과 같다.

- 단위업무명은 `대상 + 행위 + 관리` 구조의 명사구로 쓴다. 10자 안팎, 최대 25자.
- 나란히 놓는 낱말은 가운뎃점(·)으로 잇는다.
- 공사가 쓰는 정식 시설명·시스템명·제도명을 쓴다. 제목에 나온 표기를 따른다.
- 연도, 차수, 업체명, 괄호, 문서 처리 행위(알림·제출·요청)는 넣지 않는다.
- 같은 부서 안의 다른 단위업무, 기록물철명과 구별되게 짓는다.
- 기록물철 설명은 "~, ~ 및 ~ 관련 자료를 관리하는 기록물철" 문형으로 쓴다.

보존기간 제안은 선택 사항이다. 적을 때는 `references/retention-criteria.md`의 항목 번호를 근거로 든다(예: "10년(10년 1-1)"). 근거를 찾지 못하면 비워 둔다.

## 검토 기준

검토 에이전트는 제안마다 다음을 확인한다.

1. **이름 관례**: 위 「이름 짓기」와 `naming-conventions.md`에 맞는가.
2. **중복**: 같은 부서의 다른 제안·기존 단위업무와 이름이 같거나 뜻이 같은 것이 없는가.
3. **범위 겹침**: 두 제안의 근거 군집이나 기록물철 초안이 같은 문서를 가리키지 않는가. 겹치면 어느 쪽으로 합칠지 수정안을 낸다.
4. **근거 일치**: 근거 군집의 대표제목이 실제로 제안한 업무의 문서인가. 부서공통·타부서 소관 수신·혼합 군집을 근거로 쓰지 않았는가.
5. **근거 충분**: 문서 수와 연도 분포가 반복 업무임을 보여 주는가. 특정 연도에만 몰린 한시 사안을 상시 단위업무로 제안하지 않았는가.
6. **기존 단위업무 처리**: 유지·개명·통합·폐지 검토의 판단이 군집 자료와 맞는가. 폐지 검토의 사유에 확인 범위가 적혀 있는가.
7. **기록물철 초안**: 철 구분이 업무 주기나 대상에 따른 것이고, 설명이 대표제목의 문서를 포괄하는가.

## 결과 파일 형식

세 단계의 JSON 형식과 예시는 `references/output-formats.md`에 있다. 파일을 쓰기 전에 읽는다. 쓴 뒤에는 반드시 `validate.py`를 통과시킨다. 형식 오류가 남으면 보고서 스크립트가 해당 부서를 싣지 못한다.
