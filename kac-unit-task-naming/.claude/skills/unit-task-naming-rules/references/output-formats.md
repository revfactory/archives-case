# 결과 파일 형식

모든 파일은 UTF-8 JSON이다. 필드 이름과 허용 값은 `validate.py`가 검사한다.

## 1. 군집 해석: `interpret/{part}.json`

```json
{
  "part": "part_01",
  "clusters": [
    {
      "cluster_id": "c006",
      "업무내용": "계약·사업 부서가 낸 일상감사 대상의 변경사항을 받아 처리하고 현장 일상감사를 계획한다",
      "성격": "고유업무",
      "기존단위업무": {"unit_id": "U0117", "적합도": "일치"},
      "임시업무명": "일상감사",
      "비고": ""
    },
    {
      "cluster_id": "c010",
      "업무내용": "코로나 확산 방지를 위한 부서 재택근무 편성과 변경을 보고한다",
      "성격": "부서공통",
      "기존단위업무": {"unit_id": null, "적합도": "없음"},
      "임시업무명": "",
      "비고": "2021~2022년에 몰린 한시 사안"
    }
  ]
}
```

- `성격`: `고유업무`, `부서공통`, `타부서 소관 수신`, `혼합`, `판단불가`
- `적합도`: `일치`, `부분`, `없음`. `없음`이면 `unit_id`는 null
- part 파일의 모든 `cluster_id`를 한 번씩 다룬다.

## 2. 제안: `proposals.json`

```json
{
  "부서명": "감사실",
  "모드": "대조",
  "proposals": [
    {
      "proposal_id": "P001",
      "유형": "신설",
      "기존_unit_id": null,
      "제안_단위업무명": "인사·포상 사실관계 확인관리",
      "제안_소기능": "감사지원관리",
      "기록물철_초안": [
        {"기록물철명": "의원면직·포상 대상자 사실관계 확인", "설명": "의원면직 신청자와 포상 후보자의 감사·조사 진행 여부 등 사실관계 확인 요청과 확인결과 회신 관련 자료를 관리하는 기록물철"}
      ],
      "보존기간_제안": "",
      "근거_cluster_ids": ["c005"],
      "대표제목": ["의원면직 신청 관련 사실관계 확인 요청", "포상 후보자 추천 관련 사실관계 확인결과 회신"],
      "사유": "2021~2026년 내내 요청·회신 문서가 반복되나 기존 단위업무 23개 가운데 대응하는 것이 없다",
      "확신도": "보통"
    },
    {
      "proposal_id": "P002",
      "유형": "유지",
      "기존_unit_id": "U0117",
      "근거_cluster_ids": ["c006"],
      "대표제목": ["일상감사 변경사항 제출"],
      "사유": "이름과 문서가 맞는다",
      "확신도": "높음"
    }
  ],
  "보류": [
    {"cluster_id": "c010", "사유": "부서공통(복무) 성격의 한시 사안"}
  ]
}
```

필드 규칙

| 필드 | 규칙 |
| --- | --- |
| `proposal_id` | `P001` 형식, 중복 없음. 수정 단계에서도 번호를 바꾸지 않는다 |
| `유형` | 대조 모드: `신설`, `개명`, `통합·폐지 검토`, `유지`. 초안 모드: `초안`만 |
| `기존_unit_id` | 개명·통합·폐지 검토·유지에 필수. 신설·초안은 null. 대조 모드에서는 `existing_units.json`의 모든 단위업무가 정확히 한 번씩 나와야 한다 |
| `통합대상_unit_id` | 통합·폐지 검토에서 합칠 단위업무가 있을 때 |
| `준용_unit_id` | 초안에서 준용 참고 기준표의 단위업무 이름을 따랐을 때 |
| `제안_단위업무명` | 신설·개명·초안에 필수. 2~25자, 연도·괄호·마침표 없음, 부서 안에서 중복 없음 |
| `제안_소기능` | 신설·초안에 적는다 |
| `기록물철_초안` | 신설·초안에 1개 이상. 개명은 철 구성도 바꿀 때만 |
| `보존기간_제안` | 선택. 적으면 책정 기준 항목 번호를 함께 적는다 |
| `근거_cluster_ids` | 신설·개명·초안에 필수. 유지와 통합·폐지 검토는 해당 군집이 있으면 적는다 |
| `대표제목` | 근거 군집의 `대표제목`에 있는 제목을 글자 그대로 2~5개 옮긴다. 고쳐 쓰면 검사에서 걸린다 |
| `사유` | 필수 |
| `확신도` | `높음`, `보통`, `낮음` |
| `검토반영` | 수정 단계에서 검토 지적에 어떻게 대응했는지 |

`보류`에는 제안의 근거로 쓰지 않은 모든 군집을 사유와 함께 넣는다. 근거 문서 수는 적지 않는다. 보고서 스크립트가 근거 군집의 문서 수를 합산한다.

## 3. 검토: `review.json`

```json
{
  "reviews": [
    {"proposal_id": "P001", "판정": "수정필요", "지적": ["이름에 '인사·포상'과 '사실관계 확인'이 함께 있어 길다. 대표제목은 의원면직과 포상 두 경우뿐이다"], "수정안": "인사·포상 사실확인관리"},
    {"proposal_id": "P002", "판정": "통과", "지적": []}
  ],
  "누락_의견": ["보류한 c021(문서 64건)은 생산 문서가 대부분이라 고유업무로 보인다"]
}
```

- `판정`: `통과`, `수정필요`, `기각`. 통과가 아니면 `지적`을 1개 이상 적는다.
- `proposals.json`의 모든 `proposal_id`를 한 번씩 다룬다.
