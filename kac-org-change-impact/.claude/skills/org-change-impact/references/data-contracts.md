# 파일 형식

모든 파일은 UTF-8 JSON이다. 형식은 `scripts/validate.py`가 검사한다.

## 00_scenario.md

사용자가 말로 준 조직변경 시나리오 원문. 오케스트레이터가 고치지 않고 그대로 저장한다.

## 01_org_diff.json (diff_org.py가 생성)

`없어진_부서`, `새로_생긴_부서`, `상위조직이_바뀐_부서`, `업무분장이_바뀐_부서`(삭제항목·추가항목·문구수정), `이관_후보_항목`. 부서는 `기관|부서명`으로 적는다.

## 02_changes.json (org-change-interpreter가 작성)

```json
{
  "입력유형": "차수비교",
  "기준": "시행세칙 46차 → 47차",
  "확인필요": ["통합 뒤 부 이름이 정해졌는가?"],
  "events": [
    {
      "event_id": "E01",
      "유형": "부서분리",
      "요약": "신공항건설부를 신공항건설1부·2부로 분리",
      "변경전": [{"기관": "본사", "부서명": "신공항건설부"}],
      "변경후": [{"기관": "본사", "부서명": "신공항건설1부", "경로": ["부사장직할", "신공항추진단", "신공항건설1부"]}],
      "업무": [{"문구": "KAC-BIM 사업관리", "이전부서": "본사|신공항건설부", "변경부서": "본사|신공항건설1부"}],
      "근거": "세칙 45차 별표 3. 44차 신공항건설부 업무분장 1~4호가 1부·2부로 나뉨",
      "확신도": "높음",
      "분류기준표_영향": "있음"
    }
  ]
}
```

- `입력유형`: `차수비교` 또는 `시나리오`
- `유형`: 부서신설, 부서폐지, 부서통합, 부서분리, 명칭변경, 상위조직변경, 업무이관, 업무신설, 업무폐지
- `변경전`·`변경후`: `{"기관", "부서명"}` 객체 배열. 기관은 세칙 별표 3의 구분(본사, 김포공항, 항로시설본부 등). 실·단 전체가 대상이면 부서명에 실·단 이름을 적는다. 둘 중 하나는 있어야 한다.
- `업무`: 업무이관·업무신설·업무폐지에서 필수. `이전부서`·`변경부서`는 `기관|부서명` 또는 null.
- `확신도`: 높음, 보통, 낮음 / `분류기준표_영향`: 있음, 없음, 불명

## 03_candidates/{event_id}.json (impact_lookup.py가 생성)

`event`, `기준차수`, `유의`, `후보_단위업무`(unit_id, 부서1, 부서2, 중기능, 소기능, 단위업무명, 후보사유, 기록물철[file_id, 기록물철명, 보존기간], 과거_정비의견), `문서규모`(문서목록 부서명별 대응유형·연도별 문서수), `문서규모_설명`.

## 04_proposals/{event_id}.json (unit-impact-analyst가 작성)

```json
{
  "event_id": "E01",
  "proposals": [
    {
      "unit_id": "U0087",
      "조치": "부서레벨변경",
      "대상_file_ids": [],
      "변경후_부서1": "건설사업실",
      "변경후_부서2": "신공항건설1부",
      "변경후_단위업무명": null,
      "근거": "사건 E01. 단위업무 내용(제주 제2공항 사업관리)은 그대로이고 소속 실만 바뀜",
      "확신도": "높음"
    }
  ],
  "new_units": [
    {"부서1": "본사", "부서2": "IAM사업단", "소기능": "버티포트사업관리", "단위업무명": "버티포트 구축·운영", "기록물철_제안": ["버티포트 설계·시공", "버티포트 운영계획"], "근거": "신규 업무분장 6호에 대응하는 단위업무가 없음"}
  ],
  "미해결": ["통합 뒤 부 이름 미정"]
}
```

- `조치`: 부서레벨변경, 이관, 단위업무명변경, 폐지후보, 유지
- 후보 파일의 단위업무는 모두 `proposals`에 있어야 한다(영향 없으면 `유지`).
- `대상_file_ids`가 빈 배열이면 단위업무의 기록물철 전체가 대상이다.
- 부서레벨변경·이관은 `변경후_부서1`·`변경후_부서2` 필수, 단위업무명변경은 `변경후_단위업무명` 필수.

## 05_verify/{event_id}.json (change-proposal-verifier가 작성)

```json
{
  "event_id": "E01",
  "verdicts": [
    {"대상": "U0087", "판정": "타당", "의견": ""},
    {"대상": "new:1", "판정": "근거부족", "의견": "U0412 'UAM 인프라 구축'과 범위가 겹침"}
  ],
  "누락": [{"unit_id": "U0086", "사유": "신공항건설1부·2부 공동 단위업무인데 제안에 없음"}]
}
```

- `대상`: 제안의 `unit_id`, 신설 제안은 `new:{순번}`(1부터). 제안의 모든 대상에 판정이 있어야 한다.
- `판정`: 타당, 수정필요, 근거부족. 타당이 아니면 `의견` 필수.

## 06_impact_stats.json과 output/{run}/ (build_change_table.py가 생성)

- `분류기준표_변경안.csv`: 영향받는 기록물철 1건당 1행
- `신설_단위업무_제안.csv`
- `분류기준표_변경적용본.csv`: 전체 1,663행에 확정안만 적용
- `06_impact_stats.json`: 사건별 조치·상태·보존기간별 집계, 문서 규모, 검증 누락 지적, 미해결, 분석되지 않은 사건
- 상태: `확정안`(검증 타당 + 확신도 높음·보통), `검토필요`(그 밖), `미검증`(검증 파일 없음)
