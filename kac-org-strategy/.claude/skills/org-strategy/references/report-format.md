# 경영진 보고서 형식

파일: `output/{run}/조직개편_추천보고서.md`. 본문은 A4 5~8쪽 분량으로 쓰고 세부 목록은 부록에 둔다.

## 구성

1. **요약**(반 쪽 이내): 추천안 한 문장, 핵심 조치 3~5건, 영향 규모, 결정이 필요한 사항.
2. **검토 배경과 전략 방향**: 사용자가 준 전략 방향. 없으면 자료에서 확인한 문제를 기준으로 했다고 적는다.
3. **현재 조직 진단**: 진단서의 문제 가운데 추천과 관련된 것. 문제마다 근거 표기.
4. **개편 대안 비교**: 대안별 한 단락 설명과 비교표.

   | 구분 | OPT-A | OPT-B | OPT-C |
   | --- | --- | --- | --- |
   | 관점·대안명 | | | |
   | 핵심 조치 | | | |
   | 대상 단위업무 수 | `[영향 OPT-A 대상 단위업무 수=n]` | | |
   | 대상 기록물철 수 | | | |
   | 부서레벨1 소속이 바뀌는 단위업무 수 | | | |
   | 기대효과 | | | |
   | 주요 위험 | | | |
   | 규정상 절차 | | | |
   | 검토 판정 | | | |

5. **추천안**: 어느 대안(또는 대안들의 어느 조치 조합)을 왜 추천하는가. 조치별로 대상 부서, 옮기는 단위업무 묶음(대표 단위업무명과 개수), 근거, 기대효과, 위험과 완화 방법. 추천하지 않은 대안·조치와 그 이유.
6. **단계별 실행 순서**: 먼저 할 조치와 나중에 할 조치, 조치 사이의 선후 관계, 규정 개정 절차(제약 ID 인용). 기간과 인원은 자료가 없으므로 순서만 적는다.
7. **경영진이 결정할 사항**: 예·아니오로 답할 수 있는 질문 3~6개.
8. **검토 범위와 한계**: 쓴 자료, 추정에 기댄 부분, 자료가 없어 다루지 못한 것(인원, 예산, 업무량), 빠진 관점.
9. **부록**: 조치별 unit_id 전체 목록(단위업무명 포함), 근거 ID 목록, 대안 파일과 검토서 경로.

## 표기 규칙

- 사실 자료의 수치: `[근거ID 항목=값]`. 대안 영향 규모: `[영향 option_id 항목=값]`. 두 표기 모두 `check_citations.py`가 대조한다.
- 영향 규모 가운데 중첩된 항목(유형별, 부서별)은 표기로 대조되지 않는다. 본문에 쓸 때는 수치를 대안 파일에서 그대로 옮기고 `[영향 OPT-A]`처럼 출처만 붙인다.
- 추천안이 여러 대안의 조치를 조합한 것이면 합산 수치를 직접 계산해 쓰지 않는다. 조합한 조치를 담은 대안 파일 `_workspace/{run}/05_option_OPT-R.json`을 만들고 `check_option.py --write`로 영향 규모를 계산한 뒤 `[영향 OPT-R ...]`로 인용한다.
- 문장은 평서형으로 쓴다. "~할 것으로 보인다"가 반복되지 않게, 자료로 확인한 사실과 추천자의 판단을 문장 단위로 구분한다.
- 비유적 표현을 쓰지 않는다.
